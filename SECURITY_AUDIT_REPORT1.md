## A. Executive summary

**Is TRACE itself vulnerable? Yes — two genuine guard failures plus conditional/hardening gaps.** V1 path traversal arbitrary-overwrite **CONFIRMED** (absolute + `..` both succeed). V2 allowlist bypass **CONFIRMED** (any host whitelisted via `allow_target`, plus raw-`httpx` connectivity checks bypass the guard entirely). V3 is a **conditional** Windows-only shell shape + cache/version-trust gaps (not a turnkey RCE). V4 is an **intended local-tool capability** with missing allowlist/secret/DoS caps (trust-model dependent). V5 is **false positive as RCE** (list-form, hardcoded executables; port/registry hardening only). Three "safe" claims: torch shape verified safe, HTML escaping verified for examined contexts, redirect revalidation present but **partially** protective (TOCTOU/DNS + V2 defeat + raw-check bypass).

**Is TRACE a legitimate scanner? Pipeline is real and counts reproduce exactly, but findings are heuristic static hypotheses — not confirmed exploits — and the headline metrics conflate edges with attack paths.** `188 files / 38 routes / 790 nodes / 815 edges` reproduced to the integer via root scan (see §F). 815 = **edges**, not "directed attack paths" (measured endpoint paths ≈72). The 40 findings (3 critical / 25 high / 12 medium) all map to real fixture routes (labs intentional vulns + test-repository + testbed_hardcore + tests fixtures) — **no hallucinated routes** — but severities/confidences are static priors: the two "critical SQLi" and one "critical SSTI" are **false positive / strong-static at best** (details §D); BOLA/BFLA on labs are **strong-static true-shape** (intentional flaws) still awaiting runtime proof (confidence MEDIUM/HIGH, not CONFIRMED). Model/latency/accuracy claims (586ms, 390ms, 96.4%, 100% BOLA, 0.26s) are **unsupported in this env** (no weights, no pytest, no blind eval, no timing run).

**Most serious confirmed defects:** (1) SafePatcher workspace escape → any-file overwrite as user; (2) ScopeGuard `allow_target` + raw connectivity fetch → SSRF guard defeat incl. metadata host after allowlisting.
**Most consequential unsupported claims:** 815 "attack paths", per-model latencies, precision/recall/FPR, sub-second generalization, training-provenance-from-filename.
**Limits:** no pytest, no weights/GPU, Win symlink privilege blocked loop test, no live target launched, no network exfil, no PPT binary (docs used as proxy).

## D. Scanner-validity audit

### D.1 Pipeline (traced end-to-end, reproduced)

`RepositoryScanner.scan()` (`ingest/repository.py:17-50`) → `CodeParser.parse()` (`parsing/parser.py`) → `get_adapters()` (`framework/__init__.py`) per-file `can_handle` + `extract_endpoints` → `APMBuilder.build()` (`apm/builder.py:19-208`: repo→file `CONTAINS`, file→fn `CONTAINS`, file→endpoint `EXPOSES`, endpoint→handler `ROUTES_TO`, endpoint→param `RECEIVES`, auth `PROTECTS`, db `ACCESSES`, ext `CONNECTS_TO`) → `HypothesisEngine.derive_hypotheses()` (`security/hypotheses.py:51-697`, 11 rule families + codebase-wide CORS/crypto) → optional `IntelligenceOrchestrator` (SecureBERT `classifier.py` + Laya `router.py`; both deterministic fallbacks when weights absent) → testpacks (`testpacks/*`, only when target online) → `EvidenceCorrelator.correlate()` (`findings/correlate.py:28-119`: Bayesian `fusion.py`, posterior<0.40 static-only filtered, severity from hypothesis override or `SEVERITY_BY_CATEGORY`, attack path from `find_paths_to_sinks` else `find_paths_from_endpoint(depth=3)`) → `FindingStore` + Markdown/SARIF/HTML/terminal.

Model output is **prioritization, not proof**: `correlate()` labels unconfirmed as "runtime validation pending/inconclusive" with MEDIUM/POTENTIAL confidence; CONFIRMED only when `test_result.confirmed` (requires live target + testpack match).

### D.2 Route extraction accuracy

Reproduced per-fixture (see §F): vending-api 9/9 correct (FastAPI decorator regex + auth/db/ext heuristics); test-repository Dart 5/5 + Kotlin/Spring 2/2 correct; testbed_hardcore Django **over-generates**: 15 endpoints from 6 files — 5 real `urlpatterns` (`backend/views.py:60-66`) + 5 synthetic `/api/<fn-name>` from `@api_view` functions (`django.py:123-141`) + extras from `urls.py`/`server.py`/services. Consequences: spurious endpoints (`POST /api/analytics-metric-query`, `GET /api/tenant-vault-secret-entry`, `POST /api/webhook-integration-dispatch`, …) that duplicate real routes; method inference wrong once (URL-pattern default `GET` in `django.py:61-63` turns POST `analytics_metric_query` into `GET /api/v1/analytics/query`); `database_access=True` defaults (`django.py:88`, `fastapi.py:207` fallback) inflate injection priors; FastAPI `GET /api/search` got `db=True` via body heuristic (unresolved exact term — fragile).
